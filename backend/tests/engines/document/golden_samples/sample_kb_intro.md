# 文档解析与切块策略

## 为什么要切块

大语言模型的上下文有限，检索的精度也随片段变长而下降。因此 RAG 系统需要把长文档切成小块，独立建立索引。切块质量直接决定检索质量：块切得好，检索到的就是完整、聚焦的语义单元；切得差，要么语义被拦腰斩断，要么一个块混杂多个主题互相干扰。

## 常见切块策略

- **固定长度切块**：每 N 个 token 一块，可带重叠（overlap）防止边界语义被切断。实现最简单，但对结构不敏感。
- **递归字符切块**：优先按段落切，段落太长再按句子，句子太长再按字符。是大多数场景的默认选择，兼顾语义完整与长度控制。
- **Markdown / 结构化切块**：按标题层级切分，让每个块保持完整的章节语义。对技术文档、手册类内容效果最好。
- **语义切块**：用模型判断相邻句子的语义转折点，在主题变化处切开。计算成本高，效果提升有限，用得较少。

## 重叠的作用

相邻块之间保留 10–20% 的重叠内容，可以缓解边界问题：一句关键的话恰好落在两个块的交界处时，无论检索到哪个块，这句话都是完整的。

## 多模态文档的特殊处理

扫描版 PDF 没有文字层，必须先 OCR；图片中的图表需要视觉模型转成文字描述；音视频要先转写。这些模态的「解析」远比纯文本复杂，也是企业知识库落地的最大工程量所在。解析后的产物（文字、描述、转写稿）再进入统一的切块和向量化流程。

## 表格与公式

表格直接切块会打碎行列关系，通常做法是整表保留为一个块，或转换成 HTML / Markdown 表格格式；公式需要专门的识别模型转成 LaTeX 文本，否则检索时无法被文字匹配。

## 元数据

每个块除了正文还应携带元数据：来源文档、章节标题、页码、更新时间。它们用于检索后的过滤（只在某文档内搜）、展示（引用溯源）和权限控制（不同用户可见不同来源）。
